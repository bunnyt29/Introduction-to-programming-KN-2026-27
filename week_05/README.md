# Lvalue и rvalue в C++

Всеки израз в C++ има тип и категория на стойността. Например променливата `a` е от тип `int`, а изразът `a` е **lvalue**. Изразът `a + 1` също е от тип `int`, но е **rvalue**. Разликата е в това дали изразът обозначава разпознаваем обект, или изчислява стойност.

Като първо приближение: **lvalue обозначава разпознаваем обект, а rvalue обикновено дава стойност, която се използва в рамките на израза.** Това е ориентир, не пълно определение: временна стойност може да се съхранява в паметта.

## 1. Какво е lvalue?

**Lvalue** е израз, който обозначава разпознаваем обект. Обикновено можем да достигнем до него чрез име, референция или указател.

~~~cpp
int a = 1;
int b = a;    // a е lvalue и може да се използва отдясно на =

int* p = &a;  // вземаме адреса на a
*p = 7;      // *p е lvalue: обозначава същия обект като a
~~~

След изпълнението `a` има стойност `7`, а `b` остава `1`.

Променлива с `const` също е lvalue, въпреки че не можем да я променяме:

~~~cpp
const int limit = 10;
int copy = limit; // позволено: четем стойността

// limit = 20;    // грешка: limit е const
~~~

Затова lvalue **не означава непременно** „израз, на който може да се присвоява“. `limit` обозначава конкретен обект, но той не може да бъде променян.

## 2. Какво е rvalue?

**Rvalue** е израз, който не е lvalue. Той дава стойност, често временна, която се използва в израза. Обичайни примери са литералите и резултатите от аритметични операции:

~~~cpp
int a = 4;
int b = 2;

a = 9;       // 9 е rvalue
b = a + 1;   // a + 1 е rvalue; b става 5
~~~

Обикновените аритметични резултати не могат да бъдат цел на присвояване:

~~~cpp
// 9 = a;       // грешка
// a + 1 = b;   // грешка
~~~

Името `rvalue` идва от *right value*, но „може да стои само отдясно на `=`“ е само ориентир. Например `a` е lvalue и също може да стои отдясно: `b = a;`.

> Не определяйте категорията само по това дали при изчисляването се използва памет. Важното е дали **самият израз** обозначава обект, или произвежда стойност.

## 3. Адресът и категорията на израза

При обикновена променлива можем да използваме `&`, за да вземем адреса на обекта. Не можем да вземем адреса на числов литерал или на резултата от `a + 1` по същия начин:

~~~cpp
int a = 4;
int* p = &a;       // a е lvalue

// int* q = &12;     // грешка
// int* r = &(a + 1); // грешка
~~~

Тук `a` обозначава разпознаваем обект, докато `12` и `a + 1` са изрази, които дават стойности. Временен резултат може да бъде съхранен в паметта, но това само по себе си не прави израза `lvalue`.

Самият израз `&a` дава стойност от тип `int*` — адреса на `a`. Той не е lvalue, на което можем да присвояваме:

~~~cpp
// &a = p; // грешка: не можем да променим резултата от &a
~~~

## 4. `++a` и `a++` не са еднакви

В C++ префиксното увеличение `++a` връща самата променлива като lvalue. Постфиксното `a++` връща старата ѝ стойност като rvalue, а после увеличава променливата.

~~~cpp
int a = 3;

int* p = &++a; // позволено: a става 4, а ++a е lvalue
int old = a++; // old става 4, а a става 5

// int* q = &(a++); // грешка: a++ е rvalue
~~~

Разликата обяснява защо някои на пръв поглед сходни изрази могат да бъдат използвани по различен начин.

## 5. Връщане на стойност от функция

Извикването на функция, която връща `int` по стойност, дава rvalue:

~~~cpp
int calculate() {
    return 12;
}

int result = calculate(); // позволено: result получава стойност 12
// calculate() = 20;      // грешка: резултатът не е обект за присвояване
~~~

## 6. Референции към lvalue и rvalue

Референцията `int&` се свързва с променлив `int` обект, тоест с неконстантен lvalue. Чрез нея функцията може да променя оригиналния обект:

~~~cpp
void addOne(int& value) {
    ++value;
}

int number = 4;
addOne(number); // number става 5
// addOne(4);   // грешка: 4 е rvalue, а int& не се свързва с rvalue
~~~

Референцията `const int&` не позволява промяна на обекта през тази референция. Тя може да се свърже както с lvalue, така и с rvalue:

~~~cpp
void printValue(const int& value) {
    std::cout << value;
}

int number = 4;
printValue(number);     // lvalue
printValue(number + 1); // rvalue
printValue(12);         // rvalue
~~~

Когато `const int&` се свърже с rvalue, например с резултата от `number + 1`, C++ създава временен обект за тази стойност. Референцията обозначава този временен обект, който остава валиден до края на пълния израз, в който е извикана функцията. Затова функцията може да прочете стойността по време на извикването. Това е позволено, защото функцията обещава, че няма да променя стойността през `const int&`.

## 7. Изключение от простото правило за присвояване

Категорията се определя за целия израз. В C++ условният оператор може да даде lvalue, когато и двата възможни резултата обозначават подходящи обекти:

~~~cpp
int x = 3;
int y = 8;

(x < y ? y : x) = 0; // позволено: избира y и го променя на 0
~~~

Това е още една причина да не свеждаме lvalue до „името на променлива“.

## Обобщение

| Израз | Категория | Защо? |
| :--- | :--- | :--- |
| `a` | lvalue | Обозначава променливата `a`. |
| `*p` | lvalue | Обозначава обекта, към който сочи `p`. |
| `limit`, когато е `const int` | lvalue | Обозначава константен обект. |
| `9` | rvalue | Дава числова стойност. |
| `a + 1` | rvalue | Дава резултат от изчисление. |
| `++a` | lvalue | Връща самата променлива. |
| `a++` | rvalue | Дава старата стойност. |

Практическото правило е: попитайте **дали изразът обозначава разпознаваем обект**. Ако не го прави и вместо това дава стойност, изразът е rvalue.
