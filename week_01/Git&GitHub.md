# Git и GitHub

В софтуерната разработка програмите се променят непрекъснато, а често по един проект работят няколко души. За да проследяваме промените, да запазваме историята на проекта и да споделяме работата си, използваме системи за контрол на версиите.

## 1. Git и GitHub

Преди да преминем към практическата работа, е важно да разграничим Git от GitHub. Те са свързани, но не са едно и също нещо.

### Git

**Git** е разпределена система за контрол на версиите. Тя съхранява историята на проекта в локалното хранилище на компютъра ви. Всяка версия, която запазите с commit, остава част от тази история.

С Git можем да:

- запазваме отделни версии на проекта чрез **commit**;
- сравняваме промените между различни версии;
- създаваме отделни клонове (**branches**) за различни задачи;
- обединяваме работата от няколко клона;
- възстановяваме по-стара версия при необходимост.

Тази информация се съхранява локално.

### GitHub

**GitHub** е онлайн платформа за съхраняване и споделяне на Git хранилища. Там може да се намира отдалеченото копие (**remote repository**) на проекта, с което се синхронизира локалното хранилище.

При екипна работа всеки разработчик обикновено има локално копие на проекта. След като запише промените си с commit, може да ги изпрати към GitHub чрез `git push`. За да получи промените, качени от останалите, използва `git pull`. Git обединява полученото с локалната работа, когато е възможно; ако има конфликт, разработчиците трябва да го разрешат.

```text
локално хранилище                 отдалечено хранилище
       Git       ── push ──►          GitHub
       Git       ◄─ pull ───          GitHub
```

GitHub допълва Git с инструменти за работа в екип — преглед на код, pull requests, управление на задачи и проследяване на промените. Качването на промени в GitHub не означава, че те автоматично се обединяват с работата на всички останали.

| Git | GitHub |
| --- | --- |
| Работи локално на компютъра. | Работи онлайн. |
| Управлява историята и версиите на проекта. | Хоства отдалечени Git хранилища. |
| Използва команди като `commit`, `branch` и `merge`. | Предоставя `push`, `pull requests`, issues и инструменти за съвместна работа. |
| Може да се използва самостоятелно. | Използва Git за управление на хранилищата. |

GitHub не е единствената платформа за Git хранилища. Други широко използвани алтернативи са **GitLab** и **Bitbucket**.

## 2. Инсталиране и първоначална настройка

Инсталирайте [Git](https://git-scm.com/downloads), след което отворете Git Bash или терминал и задайте името и имейла си:

```bash
git config --global user.name "Вашето име"
git config --global user.email "вашият-email@example.com"
```

Проверка на настройките:

```bash
git config --global --list
```

Името и имейлът се записват като автор на вашите commit-и.

## 3. Клониране на съществуващо хранилище

Ако хранилището вече съществува в GitHub, създайте локално копие чрез `git clone`:

```bash
git clone <URL-на-GitHub-хранилището>
cd <име-на-папката>
```

След клонирането локалното копие вече съдържа проекта и неговата история. При последваща работа в екип изпълнявайте `git pull` преди да започнете, за да получите промените, качени от останалите.

## 4. Създаване на ново хранилище

За нов проект първо създайте празно хранилище в GitHub. След това, от папката на проекта на компютъра си, изпълнете:

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin <URL-на-GitHub-repository>
git push -u origin main
```

Командата `git add .` подготвя всички промени в текущата папка, които Git не игнорира. Преди нея проверете `git status` и се уверете, че не добавяте генерирани файлове, пароли или друга информация, която не трябва да бъде качвана.

`git add` подготвя състоянието на файла към момента на изпълнение на командата. Ако след това го редактирате отново, изпълнете `git add` повторно, за да включите и последните промени в commit-а.

## 5. Полезни команди

```bash
git status                           # състояние на хранилището
git add име-на-файла.cpp             # подготвя файл за commit
git diff                             # показва неподготвените промени
git diff --staged                    # показва подготвените промени
git commit -m "Описание на промяната" # записва подготвените промени локално
git log --oneline                    # кратка история на commit-ите
git branch                           # налични клонове
git remote -v                        # адреси на отдалечените хранилища
git pull                             # получава и обединява промени
git push                             # изпраща commit-и към GitHub
```
