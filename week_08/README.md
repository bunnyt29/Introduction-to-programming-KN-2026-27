# Динамична памет в C++

Досега всички масиви, които използвахме, бяха със **статично заделен размер** (например `int arr[128];`). Размерът им трябваше да е константа, известна още при компилация. В реалните задачи това създава три основни проблема:

1. **Хабене на памет:** Заделяме `MAX_SIZE = 1024`, а потребителят въвежда само 5 числа.
2. **Ограничен капацитет:** Ако потребителят въведе 2000 числа, програмата не може да ги побере.
3. **Препълване на стека (Stack Overflow):** Големи масиви (напр. `int matrix[1024][1024]` $\approx 4\text{ MB}$) могат да надхвърлят размера на стека и да сринат програмата.

Решението е **динамичното заделяне на памет** — искаме от операционната система точно толкова памет, колкото ни трябва, по време на самото изпълнение на програмата.

---

## 1. Stack (Стек) vs. Heap (Хийп)

Паметта, с която разполага една C++ програма, е разделена на няколко области. Най-важните за нас са **Stack** и **Heap**:

| Свойство | Stack (Стек) | Heap (Хийп / Free Store) |
| :--- | :--- | :--- |
| **Кой я управлява?** | Компилаторът (автоматично). | **Програмистът** (ръчно с `new` и `delete`). |
| **Кога се определя размерът?** | При компилация (трябва да е константа). | **По време на изпълнение** (може да е променлива `n`). |
| **Размер на областта** | Малък (обикновено няколко MB). | Голям (ограничен основно от RAM паметта). |
| **Скорост на заделяне** | Много бърза. | По-бавна. |
| **Живот на данните** | До края на блока `{ ... }`, в който са създадени. | Докато не ги освободим с `delete` (или до края на програмата). |
| **Достъп** | Директно чрез името на променливата. | **Само чрез указател** (пази адреса на блока в Heap-а). |

---

## 2. Оператори `new` и `delete`

За работа с динамична памет в C++ използваме операторите `new` (заделя памет в Heap-а и връща адреса ѝ) и `delete` (освобождава паметта).

### За единична променлива

```cpp
int* ptr = new int(42); // заделя 1 int в Heap-а със стойност 42
std::cout << *ptr << '\n';

delete ptr;             // освобождава паметта
ptr = nullptr;          // добра практика: нулираме указателя
```

### За динамичен масив (`new[]` и `delete[]`)

```cpp
int n;
std::cin >> n;

int* arr = new int[n];     // заделя масив от точно n елемента (неинициализирани)
// int* arr = new int[n]{}; // заделя масив от n елемента, всички инициализирани с 0

for (int i = 0; i < n; ++i) {
    std::cin >> arr[i];
}

// ... работа с масива ...

delete[] arr;   // ЗАДЪЛЖИТЕЛНО с квадратни скоби []!
arr = nullptr;
```

> **Златно правило:**
> - Всяко `new` трябва да има точно един `delete`.
> - Всяко `new[]` трябва да има точно един `delete[]`.

### Подаване на динамичен масив на функция

При подаване на функция, динамичният 1D масив се подава точно по същия начин като статичния — като указател към първия елемент:

```cpp
void printArray(const int* arr, int size) {
    for (int i = 0; i < size; ++i) {
        std::cout << arr[i] << ' ';
    }
    std::cout << '\n';
}
```

## 3. Динамични матрици (`int**`)

Динамична матрица с размери `rows × cols` най-често се представя като **масив от указатели**, където всеки указател сочи към отделен динамичен масив (един ред от матрицата):

```text
matrix (int**) ──► [ ptr0 ] ──► [ a00, a01, a02 ]
                   [ ptr1 ] ──► [ a10, a11, a12 ]
                   [ ptr2 ] ──► [ a20, a21, a22 ]
```

### Заделяне и освобождаване на матрица

Заделянето става **отвън навътре** (първо масива от редове, после всеки ред), а освобождаването — **в обратен ред** (първо всеки ред, накрая масива от указатели):

```cpp
int** allocateMatrix(int rows, int cols) {
    int** matrix = new int*[rows];
    for (int i = 0; i < rows; ++i) {
        matrix[i] = new int[cols]{};
    }
    return matrix;
}

void freeMatrix(int** matrix, int rows) {
    for (int i = 0; i < rows; ++i) {
        delete[] matrix[i]; // трием всеки ред
    }
    delete[] matrix;        // накрая трием масива от указатели
}
```

### Подаване на динамична матрица на функция

Вече **не** ни трябва константа `MAX_SIZE` в параметрите. Освен това всеки отделен ред `matrix[i]` е просто 1D масив (`int*`), така че функциите за 1D масив се преизползват директно:

```cpp
void printMatrix(const int* const* matrix, int rows, int cols) {
    for (int i = 0; i < rows; ++i) {
        printArray(matrix[i], cols); // подаваме само реда (int*), не цялата матрица
    }
}
```

*(Забележка: За достъп до елемент отново пишем `matrix[i][j]`, както при обикновена матрица. Ако функцията ще променя матрицата, типът на параметъра е `int** matrix`.)*

## 4. Важни правила и най-чести грешки

Динамичната памет не се изтрива сама, когато функцията приключи. Ако изгубим адреса или забравим да я освободим, тя остава „заклещена“ до края на програмата.

### 1) Memory Leak (Изтичане на памет)

Случва се винаги, когато заделим памет с `new` / `new[]`, но не я освободим с `delete` / `delete[]`:

- **Забравен `delete[]`:**
  ```cpp
  void badFunction(int n) {
      int* temp = new int[n];
      // ... правим нещо с temp ...
  } // temp изчезва от стека, но паметта в Heap-а остава завинаги!
  ```
- **Ранно `return` преди `delete[]`:**
  ```cpp
  int* arr = new int[n];
  if (n <= 0) {
      return -1; // ГРЕШКА: излизаме, преди да изтрием arr!
  }
  ```
  *Правило:* Винаги валидирайте входа **преди** да заделяте памет, или освободете паметта преди всяко ранно `return`.
- **Презаписване на указателя преди триене:**
  ```cpp
  int* arr = new int[5];
  arr = new int[10]; // ГРЕШКА: адресът на старите 5 елемента е изгубен!
  delete[] arr;      // трие само втория масив
  ```
  *Правило:* Винаги първо освобождавайте стария блок (`delete[] arr;`), преди да насочите указателя към нов блок.

### 2) Неясна собственост (Кой трие паметта?)

Когато функция **връща** динамично заделен масив (например `int* createArray(int n)`), тя прехвърля отговорността на извикващата функция (`main`). Извикващият код **задължително** трябва да извика `delete[]` върху върнатия указател, когато приключи работа с него.

### 3) Висящ указател (Dangling Pointer) и Double Free

```cpp
int* arr = new int[5];
delete[] arr;

// arr[0] = 10;  // ГРЕШКА (Undefined Behavior): паметта вече е освободена!
// delete[] arr; // ГРЕШКА (Double Free): срив на програмата!

arr = nullptr;   // Безопасно: delete[] nullptr е валидна празна операция
```

### 4) Несъответствие между `new[]` и `delete`

```cpp
int* arr = new int[10];
delete arr; // ГРЕШКА: за масив винаги се използва delete[] arr;
```
